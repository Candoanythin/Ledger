# 잔고일기 — 오프라인 복식 가계부

개인 휴대폰 안에서만 사용하는 **오프라인 복식부기 가계부**입니다.  
서버·로그인·광고·분석 도구를 사용하지 않으며, 장부 원문은 앱 잠금 비밀번호로 AES-GCM 암호화되어 브라우저 저장소에 보관됩니다.

## 제공 기능

- 지출·수입·계좌 이체·직접 분개를 모두 차변/대변이 같은 금액인 전표로 저장
- 기본 계정과목: 현금, 통장, 적금, 투자자산, 카드미지급금, 대출, 급여, 식비 등
- 월별 예산 및 항목별 사용액 확인
- 자산·부채·순자산과 계정별 원장
- 월 손익, 재무상태, 전체 시산표
- 암호화 백업 파일 저장 및 복원
- 분개장 CSV 내보내기
- 설치 후 인터넷 없이 사용 가능한 PWA
- 카드 명세서 파일 가져오기 및 자동 카드 등록
- 명세서의 카드사·카드 식별정보·납부은행·결제일 추출
- 지출 분류 추천, 간편결제 거래 검토, 중복 파일 방지
- 선택한 카드 사용내역을 `비용 → 카드미지급금` 복식 전표로 일괄 반영

## Android 휴대폰 설치 방법

> PWA 설치와 오프라인 캐시는 `https://` 주소에서 열어야 정상 동작합니다. `index.html` 파일을 파일 앱에서 직접 열면 암호화는 가능하지만 설치/오프라인 캐시는 제한될 수 있습니다.

1. `offline-ledger` 폴더를 개인적으로 신뢰하는 HTTPS 웹 호스팅에 올립니다.
   - 예: 개인 GitHub Pages, 개인 Cloudflare Pages, 개인 NAS의 HTTPS 주소
   - 회사 PC나 회사 저장소에는 개인 장부 백업을 올리지 않는 것을 권장합니다.
2. Android의 **Chrome**에서 `https://내-주소/offline-ledger/`를 엽니다.
3. Chrome 메뉴 `⋮` → **앱 설치** 또는 **홈 화면에 추가**를 누릅니다.
4. 설치한 **잔고일기**를 열고 숫자 4자리 이상의 앱 잠금 비밀번호를 두 번 입력합니다.
5. 설정(⚙) → **백업 파일 저장**으로 첫 암호화 백업을 보관합니다.

## 일상 사용 예시

### 현금으로 점심 10,000원 지출

- 유형: `지출`
- 분류: `식비`
- 결제수단: `현금`

자동 분개: **차변 식비 10,000원 / 대변 현금 10,000원**

### 급여 3,000,000원 입금

- 유형: `수입`
- 분류: `급여`
- 결제수단: `입출금통장`

자동 분개: **차변 입출금통장 3,000,000원 / 대변 급여 3,000,000원**

### 통장에서 적금으로 500,000원 이체

- 유형: `이체`
- 보내는 곳: `입출금통장`
- 받는 곳: `비상금/적금`

자동 분개: **차변 비상금/적금 500,000원 / 대변 입출금통장 500,000원**

## 카드 명세서 가져오기

1. 하단 **카드** 탭 → **파일 선택**에서 카드 명세서 파일을 선택합니다.
2. HTML 형식 XLS, CSV, 탭 구분 텍스트는 브라우저 안에서 분석됩니다. 원본 명세서는 저장하거나 외부로 전송하지 않습니다.
3. 같은 원본 파일을 다시 선택하면 파일 해시로 인식하여 중복으로 가져오지 않습니다.
4. 자동 등록된 카드에는 카드사·카드 식별정보·납부은행·결제일이 표시됩니다. 누락된 정보는 카드 목록에서 직접 수정합니다.
5. **검토할 내역**에서 지출 계정을 확인·수정한 뒤 선택한 거래만 반영합니다.
   - 일반 카드 사용: **차변 비용 / 대변 해당 카드 미지급금**
   - 취소·환불: **차변 해당 카드 미지급금 / 대변 비용**
   - 카카오페이·네이버페이 등 간편결제는 실제 사용처가 명세서에 부족할 수 있으므로 반드시 분류를 확인합니다.
6. 카드대금이 실제로 통장에서 출금될 때에는 별도 이체로 **차변 카드미지급금 / 대변 입출금통장**을 기록합니다. 카드 사용내역을 다시 비용 처리하지 않습니다.

> `.xls` 확장자라도 구형 Excel 바이너리 형식인 파일은 외부 라이브러리 없이 안전하게 읽을 수 없습니다. Excel에서 해당 파일을 열어 **다른 이름으로 저장 → CSV UTF-8**로 저장한 다음 가져오세요.

## GitHub Pages 배포 및 업데이트

1. 개인 GitHub 저장소의 루트에 `index.html`, `sw.js`, `manifest.webmanifest`, `icon.svg`를 올립니다. `data/` 폴더와 실제 명세서·백업 파일은 올리지 않습니다.
2. GitHub 저장소 **Settings → Pages → Deploy from a branch**에서 배포 브랜치와 `/ (root)`를 선택합니다.
3. 배포 주소를 Android Chrome에서 열어 **앱 설치**를 실행합니다.
4. 앱을 수정할 때에는 `sw.js`의 `CACHE_NAME` 버전을 올린 뒤 함께 배포합니다. 설치된 앱을 완전히 닫았다 다시 열면 새 캐시가 적용됩니다.
5. 장부 자체는 GitHub에 저장되지 않습니다. 기기 변경·브라우저 초기화 전에는 앱 설정에서 암호화 백업을 따로 저장합니다.

## 보안 및 백업 원칙

- 비밀번호는 복구할 수 없습니다. 분실하면 기존 장부를 열 수 없습니다.
- 앱 데이터 삭제, 브라우저 초기화, 휴대폰 분실/교체 시 로컬 장부가 사라질 수 있습니다.
- 월 1회 이상 암호화 백업 파일을 개인 클라우드·개인 PC·암호화 USB처럼 신뢰하는 개인 저장 위치에 보관하세요.
- 백업 파일은 **백업 당시의 앱 잠금 비밀번호**가 있어야 열 수 있습니다.
- CSV는 사람이 읽을 수 있는 일반 텍스트이므로 필요한 경우에만 내보내고, 민감한 기기에 남기지 마세요.
- 회사 PC에서는 백업 JSON 또는 CSV를 열지 않는 것을 권장합니다. 회사 PC에서는 개인 가계부의 화면만 참고하는 용도로 사용하세요.

## 데이터 구조 및 제약

- 장부 데이터는 사용 중인 브라우저 프로필의 `localStorage`에 암호문 형태로 저장됩니다.
- 이 첫 버전은 단일 Android 기기에서의 입력을 기준으로 합니다.
- 자동 은행/카드 연동과 여러 기기 실시간 동기화는 의도적으로 포함하지 않았습니다.
- 다른 기기로 옮길 때는 기존 기기에서 백업을 저장한 뒤 새 기기에서 복원합니다.
